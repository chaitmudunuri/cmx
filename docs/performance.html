Performance

CMX publishes its benchmark harness in the repository so these numbers can be checked, and anyone can reproduce them on their own machine.

Methodology

The harness is scripts/bench.mjs in the repository. It launches the release binary and samples it with ps, rather than trusting a single end-to-end wall-clock reading.

  • Sampling. ps -o pid=,%cpu=,rss= every 150 ms. Where the binary spawns helper or webview processes, the highest-CPU process is tracked.
  • Ready detection. Startup ends when CPU stays at or below 5% for 4 consecutive settle checks taken every 50 ms. This detects the end of the launch burst — JIT, first paint, preloads — rather than a fixed sleep. A 15 s hard cap prevents a hang from reading as a slow start.
  • Steady state. Sampling continues for 5 s after ready (default; --window to change). Average and peak are taken over that window.
  • Statistics. Median, mean, min and max. The published table uses the median.
  • Machine-readable output. Each run emits a __CMX_BENCH__ JSON line so CI can consume the numbers directly.

Known limitations. The harness reads %CPU and RSS via ps, so it runs on macOS and Linux but not Windows. Total physical memory comes from sysctl hw.memsize, which is macOS-only; elsewhere the comparison falls back to an assumed 8 GB. Treat the percentage-of-RAM figure as a macOS result.

Reproduce

pnpm tauri build     # build the release binary first
pnpm bench --runs 5  # profile it
FlagMeaning
--runs <n>Launches to average over (default 1).
--window <ms>Sampling window after ready (default 5000).
--bin <path>Explicit binary path, skipping auto-discovery.

Numbers for a different machine, a different build or a different OS will differ — that is the point. Please open an issue with your __CMX_BENCH__ output if you see something surprising.
